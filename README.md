# gpu-hang-capture

> [!WARNING]
> **This project was generated by an AI assistant (Claude) while helping debug a
> GPU freeze on one laptop.** A human tested it on that one machine and is
> publishing it in case it helps someone else. It has not been tested more
> widely. It runs as root, so read the script (about 130 lines of bash) before
> you install it.

Saves the Intel i915 GPU error state, and the context around it, the moment
the GPU hangs, so the data is still there after the reboot you will probably
need.

## The problem

When an Intel iGPU hangs badly enough, the i915 driver can't reset it. The
kernel log then shows something like:

```
i915 0000:00:02.0: [drm] GPU HANG: ecode 12:1:859ffffb, in Xorg [1923]
i915 0000:00:02.0: [drm] GPU error state saved to /sys/class/drm/card0/error
i915 0000:00:02.0: [drm] *ERROR* GT0: Failed to reset chip
i915 0000:00:02.0: [drm] device wedged, needs recovery
```

X freezes, switching to a text console often stops working too, and you have
to reboot. The `error` file the kernel mentions is the main thing i915
developers ask for in a bug report, and it is gone after the reboot.

This service watches the kernel log as root. When a hang shows up, it copies
everything useful to disk and syncs it, all without anyone needing to do
anything while the screen is frozen.

## What gets saved

Each hang gets its own directory, `/var/log/gpu-hang/YYYY-MM-DD_HHMMSS/`:

| File | Contents |
|---|---|
| `trigger.txt` | the kernel log line that triggered the capture |
| `card0-error.txt.gz` | the i915 GPU error state (the main item for bug reports) |
| `card0-forcewake.txt` | forcewake state per power domain |
| `card0-engine_info.txt` | per-engine state and pending requests |
| `card0-guc_info.txt`, `card0-huc_info.txt` | GuC/HuC firmware versions and status |
| `card0-guc_log.txt.gz` | GuC firmware log (mostly empty unless `i915.guc_log_level` is set) |
| `dmesg.txt`, `journal.txt.gz` | kernel log and the last 15 minutes of the system journal |
| `system.txt` | kernel, command line, firmware/Mesa/Xorg versions, BIOS version, top processes |
| `*Xorg.0.log` | Xorg log(s) |

The directory is readable by root only, because it contains the journal and
the process list of all users. Only the newest 20 captures are kept.

## Install

```sh
sudo install -m755 gpu-hang-capture /usr/local/sbin/
sudo install -m644 gpu-hang-capture.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now gpu-hang-capture

# check that capturing works (creates one directory without a real hang)
sudo /usr/local/sbin/gpu-hang-capture --test
sudo ls -l /var/log/gpu-hang/
```

Requirements: bash, systemd/journald, util-linux (`setpriv`, `dmesg`),
coreutils, and a mounted debugfs (`/sys/kernel/debug`, the default on most
distros). `dpkg` and `lspci` are optional; only `system.txt` uses them.

## When the GPU hangs

1. Wait about 30 seconds. The capture takes a few seconds, and the service
   logs `capture done: <dir>` to the journal (`journalctl -t gpu-hang-capture`)
   when it's finished.
2. Reboot. If nothing responds, use the magic SysRq keys
   (Alt+SysRq+R, E, I, S, U, B), which sync and unmount filesystems cleanly.
3. Attach the capture directory to a bug report at
   <https://gitlab.freedesktop.org/drm/i915/kernel/-/issues>.

To get a more useful GuC log, add `i915.guc_log_level=2` to the kernel command
line. This costs a little overhead, so only turn it on while you're chasing a
hang.

## Uninstall

```sh
sudo systemctl disable --now gpu-hang-capture
sudo rm /usr/local/sbin/gpu-hang-capture /etc/systemd/system/gpu-hang-capture.service
sudo rm -r /var/log/gpu-hang    # optional: removes all captures
```

## Limitations

- Written for and tested on **i915** only (Raptor Lake-P, kernel 7.2, Debian).
  The `xe` driver uses different paths and is not handled.
- The debugfs file names change between kernel versions. Missing files are
  simply skipped, so a capture may be incomplete on other kernels.
- If the hang takes down the whole machine (not just the GPU), nothing can run
  and nothing is captured.

See [DESIGN.md](DESIGN.md) for the reasoning behind each decision and the
security considerations.
