# Design notes

> Generated by an AI assistant (Claude) together with the README and script.
> These notes record why things are the way they are, so others can change
> them with confidence.

## Origin

The script came out of debugging one freeze on a Framework 13 (i7-1360P,
Raptor Lake-P, i915, kernel 7.2.10, GuC 70.49.4). The render engine hung, the
GuC failed to reset it, the media engines (vdbox0/vdbox2/vebox0) stopped
acknowledging forcewake, the full GT reset timed out, and i915 marked the
device wedged. Xorg froze and switching to a text console didn't work, so
nobody could save `/sys/class/drm/card0/error` by hand before rebooting.

## Goals

- Capture without anyone doing anything: the screen may be frozen and input dead.
- Never block on the wedged GPU.
- Make sure the data survives a hard reset.
- Stay small and readable, because it runs as root.

## Decisions

**Trigger: follow `journalctl -k`.** Simple, needs no udev rules, and gives us
the triggering line. Alternatives considered:
- *udev "wedged" uevent* (newer kernels send `WEDGED=` on the drm device):
  cleaner, but it only fires once the device is already wedged, and older
  kernels don't send it. It could be added as a second trigger.
- *Polling `card*/error`*: works without the journal, but it's slower and
  doesn't see the forcewake warnings that come before the hang.

**Trigger patterns** (`TRIGGER`): taken from the real log. They include the
forcewake warnings so a capture starts even if the hang message never arrives.

**Debounce of 120 s.** One hang produced about 130 matching lines within 20 s.
One capture per incident is enough.

**`sleep 3` before reading.** "GPU HANG" is logged just before the error state
is saved. Trigger on the earliest line, then wait.

**`timeout 15` on every read.** The device may be wedged. Reading the error
state worked in testing, but debugfs files that touch the hardware could
block.

**Clear `card*/error` after saving.** i915 keeps only the first error state
until it is cleared. Without clearing, a second hang in the same boot would
not be recorded. The file is only cleared when it held a real error state.

**debugfs: use `dri/<pci-addr>` only.** The same device also shows up as
`dri/0` and `dri/128` (render node). Reading all three gave three identical
copies. If the PCI-address directory doesn't exist, the script falls back to
`dri/<minor>`.

**debugfs paths** (`gt0/forcewake`, `gt0/uc/*`, `i915_engine_info`) are
specific to the kernel version. Missing files are skipped silently. Adjust
them for other kernels or for the `xe` driver.

**`sync` at the end.** People usually reboot with SysRq or the power button
right after a freeze.

**Debian-specific bits.** `dpkg -l` and `lspci -s 00:02.0` (the usual iGPU
address) in `system.txt`. Both fail harmlessly elsewhere.

## Security

The script runs as root for as long as the machine is up, so it was reviewed
with that in mind.

**Input from the log.** Log lines are only matched against a fixed regex and
written to `trigger.txt` with `printf '%s'`. They are never evaluated or used
in a path. Only root can write to `/dev/kmsg`, so an unprivileged user can't
fake a trigger. Even if a trigger were faked, the result is only an extra
capture, which the debounce and retention limits keep bounded.

**Files in user-controlled places.** The Xorg log under
`/home/*/.local/share/xorg/` belongs to the user, who could replace it with a
symlink or something else. The first version copied it as root, which could
have copied files the user isn't allowed to read into the capture. Now
`grab_as_owner` reads it with the uid/gid of the file's owner (`setpriv`), so
it only gets what that owner could read anyway. Reads are size-limited
(`MAXSIZE`) and time-limited, which covers huge files and FIFOs. Output file
names are sanitised with `tr`.

**Confidentiality of captures.** Captures contain the system journal, the
process list with arguments, and GPU state that may include buffer contents.
The first version wrote them world-readable. Now: `umask 077`, `OUTDIR` is
mode 700, and the unit sets `LogsDirectoryMode=0700`.

**Disk usage.** At most one capture per 120 s, at most `MAXSIZE` per file, and
only the newest `KEEP` (20) capture directories are kept. `prune` only matches
directory names in the exact timestamp format the script creates.

**Environment.** `PATH` and `LC_ALL` are set explicitly. `OUTDIR` can be
overridden from the environment; that is only meaningful for root and is
intended.

**systemd hardening.** `ProtectSystem=full`, `ProtectHome=read-only`,
`PrivateTmp`, `NoNewPrivileges`. Deliberately *not* used:
`ProtectKernelTunables` (makes `/sys` read-only, so the error state can't be
cleared), `ProtectKernelLogs` (hides dmesg/kmsg), and `PrivateDevices` and
capability restrictions (the debugfs and sysfs reads need full root). These
could be tightened further after testing with `systemd-analyze security`.

**Known residual risk.** The tools it calls (journalctl, dmesg, gzip, ps) run
as root and process kernel and journal data. That is the same trust level as
running them by hand.

## Ideas / TODO

- Add the udev `WEDGED` uevent as a second trigger.
- Support the `xe` driver (`/sys/class/drm/card*/device/devcoredump`, xe debugfs layout).
- Optionally try recovery after capturing (e.g. restart the display manager).
  Deliberately left out for now: the capture should never make things worse.
- Make the lspci address configurable for systems with more than one GPU.
